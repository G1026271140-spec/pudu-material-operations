## 首次接手

1. 由原负责人单独交接：Linux 独立登录方式、GitLab 维护权限、飞书应用和两套 Base 的维护权限、Cloudflare/域名权限、备份读取权限。密码、App Secret、Tunnel Token 不写在交接文档。
2. 用自己的 Linux 账号登录，执行 `id`、`sudo -v`，确认工作目录归属自己；不借用另一人的会话。
3. 在自己的工作目录运行 `git status --short`、`git branch --show-current`、`sudo pudu-release --check`。有未提交修改时先确认归属，不清理或覆盖。
4. 运行 `scripts/ops_status.py`，核对本地/公网版本、GitLab SHA、线上 release、10 个常驻服务、3 个 timer、队列和最新日校验记录。
5. 使用本人的飞书账号登录网页检查角色；需要管理网页业务时，由现有管理员在“系统工具 → 用户权限管理”授予相应业务角色。

`pudu-release` 当前显式允许两个运维账号。将来增加第三人，须同时调整安装脚本和发布工具的账号白名单、建立个人工作区、验证 sudo 和 GitLab 身份，按正式变更提交；不能只新建 Linux 用户便假定可发布。
