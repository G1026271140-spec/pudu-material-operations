# 每次变更的验收清单

## 实施前

- [ ] 已读现行 `AGENTS.md` 和业务规则；需求 / 补充被准确记录。
- [ ] 确认本人工作区、分支、未提交修改归属、GitLab 头和线上 SHA。
- [ ] 查清受影响的 API、角色、飞书字段、数据库列、jobs / outbox / effects。
- [ ] 库存、额度、删除、权限和通知有隔离验证方案，未对真实员工做测试。

## 开发和发布

- [ ] 本地业务、审计、幂等和 outbox 的事务边界保持。
- [ ] 需要时迁移已在隔离库验证，可重复执行；已备份生产并记录实际应用。
- [ ] 相关测试通过；正式发布入口完成全套测试、前端构建、版本递增。
- [ ] 本次工程记录和代码在 GitLab，可用提交和 release-audit 追溯。
- [ ] 由 `sudo pudu-release` 完成上线，没有强推或修改 live source。

## 线上验收

- [ ] 本地 / 公网健康一致，版本和 Git SHA 与发布一致。
- [ ] Web、business、effects、card、bridge、assets、english、三个 outbox 服务正常。
- [ ] 正在处理的队列已核实；没有因本次变更新增的积压 / 冲突 / 失败。历史 failed 明确区分。
- [ ] 涉及业务的字段 / 关联 / 数量或权限已只读核对；任务不是仅入队。
- [ ] 消息变更验证实际 effect / message_id，模拟测试没有给员工发通知。
- [ ] backup / reconcile / contacts timer 保持原时间，最新结果可查；oneshot 不要求常驻。
- [ ] 备份完整，若本次触及持久化 / 恢复逻辑则独立恢复并验证摘要。
- [ ] 对话结果、规则变化、未完成项已归档；新运维人员无需依赖旧聊天即可继续。

未勾选项目写原因和下一步。低影响文档编辑不制造真实业务测试；发布管道已有的检查继续执行。
