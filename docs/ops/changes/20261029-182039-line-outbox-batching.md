## 最终行为

- 仅 primary 的“申请明细”创建 / 更新进入批量路径，单批最多 50 条。相同 lane / table / operation / job；job 为空时必须是同一唯一所属申请及相同关联值。其他来源 / 主申请审批触发 / 删除仍走原路径。不同申请和普通 / 文化通道不混在一起。
- 更新先按 record_id 批量读取，逐条验证与旧 Worker 相同的 baseline / target 字段冲突规则，正常情况再一次 batch_update。响应按 record_id 核对内容，不依赖返回顺序；内容不完整时再批量回读，不以 HTTP 成功或入队冒充完成。
- 创建每批只读一次来源表按“明细编号”查重，同编号不同内容或重复编号单独冲突，不采用错误记录；批量创建响应以编号对应，不按位置配对。响应缺失时重新查来源。超时 / 部分成功后重试先找已存在记录，避免重复新建。
- 每条 outbox ID、local_version、claim_token、错误、逐条审计及原依赖均保留。主申请仍等待所有明细及删除同步完成、飞书反向关联完整，才能写入库存核实触发字段。原卡片继续等待对应数据任务。
- SKIP LOCKED、每记录会话锁、全程共享日核对锁及租约校验保留；被其他同步持锁的行单独等待，旧版本不跨过在途版本，过期 claim 不写来源或完成新租约。每条完成审计附 batch_id / batch_size，最近批次统计只在本地 documents/outbox-line-batch:<lane> 保存，不产生员工通知或飞书任务表记录。
