# 固定业务规则

本文件表达用户最后确认并已上线的规则。以后需求如改变规则，应在变更记录中明确引用旧规则、新规则和授权来源，然后同步修改此文件及测试。

## 数据流与并发

1. 所有前端业务操作先在 PostgreSQL 的同一事务中保存业务字段、审计、幂等结果和 outbox；本地提交后页面即可读到结果。
2. 队列提交只持久保存任务并返回，不在 HTTP 中执行当前或前面的 Worker 任务；待处理不冒充完成。普通物料 / 文化周边申请原有本地业务事务保持不变。外部回调 / 通讯录刷新使用独立 inbound 线程，业务通道次序、幂等和校验保留。
3. 后台 outbox Worker 按记录版本和依赖同步飞书。一次发布从领取到远端 HTTP 完成由同一 session guard 持有校验共享锁；领取及批量领取在 guard 已持锁时不得在另一数据库连接重复申请同一锁，否则会与等待中的全量校验互相阻塞。独立调用无 guard 时仍需事务共享锁。普通主业务申请明细按同通道 / 同表 / 同操作及同 job 分批创建或更新，单批最多 50；无 job 时仅合并同一唯一所属申请。批量前逐条校验来源字段，完成按编号 / 记录 ID 和内容核对，错误 / 租约 / 版本 / 审计仍逐条保留。请求超时先核对已存在数据，不盲目重复创建；审批头和原卡片仍等全量明细完成及关联回链。通知 effects 等待对应数据同步完成，不因任务入队就报完成；事务内不等待飞书 HTTP。
4. 每天 **03:00 Asia/Shanghai** 完整读取飞书 23 张来源表，以飞书为准更新本地，包括手动修改及清空；全量预取和字段核对通过后才应用。未取得远端 ID 的本地新建记录保留。
管理员可在虚拟数据库手动启动相同的全量飞书权威校验。须确认后异步持久入队，由 inbound Worker 在业务事务之外读取全部来源；字段 / 记录完整预取通过才单事务应用。与每天 03:00 共用 reconciliation 锁，重复点击 / 多管理员同时启动复用同一待处理任务。显示每 2 秒刷新的读取表数、阶段、完成增改删与冲突计数；失败留档，手动再次启动，不自动重复覆盖；不写飞书任务队列、不创建通知。

5. 日校验与旧本地写入冲突时保留审计和 conflict，不能直接重放旧任务覆盖飞书；普通飞书手改冲突也不能借“最后提交”静默覆盖。
6. 网页字段采用服务器最后成功提交的事务顺序，提交字段覆盖对应字段；客户端时间不决定先后。幂等重试不重新执行。库存、额度、角色、最后管理员保护仍必须校验。
7. 普通物料与文化周边业务通道可以并发；各通道旧任务先处理，单条记录的飞书发布按 local_version 排序。当前只启动 ordinary / cultural / admin 三条 outbox 服务，不能把任务发给无人消费的 notification lane。
8. 代码部署通过两个个人工作区及唯一发布锁串行处理，后提交的一方赢得重叠文本修改，非重叠修改保留。结构性冲突或测试失败停止发布，不能强推或直接覆盖整棵目录。

## 导航和权限

| 分组 | 顺序 |
|---|---|
| 历史数据 | 申请记录与额度 |
| 后台编辑 | 配货与发货 → 物料管理 → 企业文化衫管理 |
| 系统工具 | 用户权限管理 → 虚拟数据库 → 后台任务 |

| 身份 | 当前业务边界 |
|---|---|
| 普通申请人 / 销售 | 申领，查看自己的三类历史和额度，查看本人发货信息；不得编辑发货 |
| HR | 全公司文化周边及企业文化衫记录、相应驳回；企业文化衫管理；没有管理员角色时不看全公司普通物料历史 |
| 管理员 | 全部类型历史与个人切换、配货、物料管理、发货编辑、服饰管理、用户权限、虚拟数据库 |
| 中台 | 查看全部符合条件的发货申请，编辑日期、物流文字和图片，是否发货由审批通过或日历提交真实物流信息自动更新；不开放配货及其他后台工具 |
| 区域市场经理及其他组合 | 沿用现有代码及飞书角色定义，不因编辑界面便利扩大权限；多个启用角色取并集 |

前端隐藏入口不代替后端鉴权。身份关联必须用 open_id，不凭姓名或 URL 扩大数据范围。未启用的角色记录不授予权限。

## 物料、文化周边和企业文化衫

- 前端显示字段保留飞书稳定表 ID / 字段 ID / 数据库列的一一映射。可编辑业务字段按角色开放；公式、汇总值和编号等通过来源字段或系统逻辑更新，不能任意写计算结果。
- 文化周边申领的文化夹克（含休闲商务夹克历史名称）仅对飞书通讯录直接部门为市场营销部、Dream组或品牌部的账号显示；任一部门命中即可。目录、图片 / 品类标签、申领前端及服务端共同过滤，按当前本地同步通讯录中的部门 ID 与成员归属判断，不能信任表单部门文字、姓名、路径或角色。申请人和已登录提交人均须符合，代选其他部门人员不能申领；其他文化周边、后台库存维护和历史记录保持原规则。缺身份 / 通讯录匹配默认拒绝夹克，不自动扩大到下级部门。
- 虚拟数据库增加仅管理员开放的“库存查询”页签，按库存类型、品类、型号 / 尺码、语种、战区及编码检索普通物料、文化周边、企业文化衫的实际库存规格。保存目标整数库存，按行锁内最新值计算差额，同一事务保存库存、库存修正流水、操作人审计、幂等结果及飞书 outbox；不额外发送管理员通知。普通物料 / 文化周边修改“当前库存”；文化周边保留正库存时的人工停用开关。企业文化衫只调整行政源表“入库/纠正”，保留原始库存、表格兑换、系统兑换与个人额度，重新计算“最新库存”，不直接写公式字段。同步冲突记录须先核对来源。两个管理员仍按最后成功事务提交更新，旧编辑器的差额不能用于覆盖新的累计纠正。
- 普通物料的有效品类 × 型号 × 语种组合应完整匹配，不能只修个别报错组合，也不能模糊匹配后扣错库存。 完整目录对管理员和区域市场经理开放的规则必须在页面和最终提交两侧一致；普通销售不因此获得隐藏规格。品类中英括号或空格变化沿用统一品类匹配键，型号、语种必须准确对应，禁止退回其他规格。旧库存查询 / 纠正流水也使用统一键；重复规格须核对物料编码，不能任意取一条。已存在但权限不符时给出权限提示，不能误报未同步。
- 新增 / 编辑品类支持可选图片。手填全新型号时可独立选择或填写产品线；型号、语种、战区位于品类管理下的次级选项。
- 采购补库按品类定义分组，桌面每行 6 张卡片；所有申请明细按品类分组。
- 配货新增明细默认选择尚未使用的规格；修改型号优先保留当前语种，选到同一规格自动合并数量和备注，保留其他规格；不能把同品类的不同型号 / 语种误合并。统一提交前再次规范草稿，后端仍验证规格唯一性；合并后删除未保留的旧明细，避免重复计量。
- 自动下单批次号由日期和完整生成幂等键的摘要组成，不截取通用 allocation 前缀。飞书创建查重以完整“生成幂等键”为批次身份，明细以“批次明细编号”为身份；同键不同内容仍报冲突，不能错认或覆盖其他申请的批次。编号碰撞恢复只修复尚未同步的已核实冲突批次，并保留审计 / 原 outbox ID，禁止重跑配货、审批、扣库或重新发送卡片；原卡片仍等待数据同步完成后更新。
- 配货台待核实列表按北京时间提交日期从新到旧分组，缺日期保留；管理员可添加 / 编辑 / 清空自定义标签（40 字）和跟进备注（1000 字）。非空标签使整张卡片呈黄色，单独备注不变黄；字段独立于申请人原备注。保存先 PG 同事务 / 审计 / 幂等 / 本地任务，再 outbox 写飞书“待核实标签 / 待核实备注”，不核实库存、不启动审批、不改变数量或发送通知。已核实或非普通物料申请不能从此入口保存。
- 配货整组分装作用于本批同品类全部明细。上方表格改语种、数量和比例，下方型号框选池切换型号，选中标蓝；切换品类保留草稿，提交不影响其他品类。
- 企业文化衫管理只开放 HR / 管理员，直接对应行政源表。支持新款式、展示名称、图片、是否展示、累计领取上限和尺码；已有领用历史的规格禁止删除，使用下架保留历史。
- 额度仅展示当前开放申领的款式；隐藏款式的历史和累计保留。开放款式即使库存 / 剩余额度为零也不隐藏。桌面每行 5 项，不显示上限。
- 文化衫和文化周边支持勾选明细后部分驳回，只恢复所选整行已发放数量及对应额度；保留原申请数量，不重复退库。所选行发放量归零，未选行不变；仍有有效行时界面显示“部分驳回”，源表状态保留“已发放”；全退后为“已驳回”。普通物料不走此接口。
- 用户权限页实时刷新完整通讯录，失败保留旧数据并报错；缺失人员默认销售。相同账号的启用角色取并集，历史累计合并不能相加放大；不得把停用账号重新启用。权限修改同样先本地后飞书权限记录表。

## 发货与通知

- “配货与发货”包含配货、发货日历两个页签；配货仅管理员，中台只能编辑发货，普通申请人只能看本人。
- 日历列出已核实库存的有效普通物料申请，以“是否发货”区分未发货 / 已发货，支持发货日和要求到达开始日；缺日期单据保留，不能漏单。
- 管理员 / 中台可编辑发货日期、发货单号及文字信息、发货图片；是否发货由后台规则自动更新。暂存后统一提交，确认原文：**发货信息即将同步给申请人，请确定提交**。
- 按 2026-10-29 用户最新确认，将状态和通知分开：普通物料原生审批 `APPROVED` 后自动勾选“是否发货”，不要求物流信息或明细完整回写。验证审批实例属于当前申请；不改写审批数量、明细状态、出库流水或库存。
- 后续新建普通物料申请默认填写“发货单号及文字信息”=“待补充”，发货图片放明确标注待补充的共用示例图；随申请头同一 PG 事务保存，复用媒体且由 outbox 后台上传和写飞书，不在请求中访问飞书。已有真实字段不被默认值覆盖，幂等重试不新建。
- 审批通过前填写的物流文字和发货图片，由 VM Worker 读取匹配本申请的最终 APPROVED 表单，下载真实图片至本地媒体，再与申请字段、审计及 outbox 同事务保存并后台写飞书。每个通过实例导入一次；已由日历明确提交提前发货时，审批只通过，不再导入 / 补齐 / 替换两项物流字段或下载审批图片；其余场景日历已有真实物流文字 / 实际图片按字段优先保留，审批仅补空白或占位，两项都填好也不再下载或改写审批图片，后续网页编辑也不被旧审批覆盖；不重跑 AnyCross 扣库或审批。图片失败仍按审批勾选已发货并重试，真实物流至少一项后才通知，附件回读不重复通知。
- 默认“待补充”和示例图片仅为占位，不算有效物流信息。替换真实文字或上传实际发货图片后再触发申请人发货通知；审批通过自动勾选已发货的规则保留。
- 2026-10-29 最新补充：管理员 / 中台在发货日历统一提交真实物流文字或实际图片至少一项，PG 同事务立即勾选已发货；暂存不生效。后台等待相应飞书字段同步成功后即通知原申请人，允许审批 PENDING / 尚未创建；终态驳回 / 撤回仍禁止。保存 calendar_revision 和 early_dispatch 及实例身份，只给日历明确提交这一来源提前发货授权，飞书普通手改不取得提前授权。后续审批不重发同一通知，不改写库存 / 发放数量 / 审批流程。
- 已发货后，仅发货日历新的有效物流 / 日期提交可以再次通知。相同幂等提交、无变化保存、附件本地 / 飞书形态转换、审批回写和源表校验不构成新的重复通知。通知记录保存日历提交版本并在发送前核对，旧未发送内容被最新提交替代；已尝试发送的未知结果保留原 UUID 和顺序。日期改变继续用日期变更卡片，其他发货通知仍用已发货卡片及申请人只读链接。
- 非提前发货的申请在审批通过后，即使无物流也显示已发货、待填写物流信息；物流至少一项有效才首次通知。不能把收件人改为文字收货人。历史已通过单据可补齐勾选，不批量补发历史通知。
- 卡片中系统生成的“联系管理员 / 找管理员申领”名单，在每次新发送或后续业务更新原卡片前，直接读取 PG 权限表中已启用且含管理员角色的账号；重复启用记录按账号去重取并集，停用记录不授予角色。权限本地保存后即可用于后续卡片，不等飞书 outbox 完成。仅刷新系统联系人文字，不改变原消息接收人、按钮、明细或业务状态，不扫描 / 批量改写历史已发送卡片。未知发送结果重试保留首次 UUID 和正文，取得原消息 ID 后仅 PATCH 其联系人；已确认的消息 ID 持久化后重试只更新该原卡片。
- 飞书申请单变更回调 1 秒合并延迟后刷新，bridge 每 15 秒完整补偿读取申请单、明细、库存、流水；网络及源端处理另计。页面 3 秒检查数据库版本，编辑草稿不被后台刷新覆盖。每天 03:00 的 23 表全量校验保持不变。
- 初次启用先建立源表历史基线，不自动补发旧物流通知，不重跑历史审批或扣库。库存核实触发字段等待本单明细 outbox 及飞书反向关联完整后才发布；跨通道依赖和记录顺序仍生效。
- 申请人发货通知为卡片，已发货标题 **您的物料申请已发货**。发货日期改变时发送 **物料发货时间变更通知** 卡片，包含原日期和新日期。
- 申请人查看链接为 owner-only 只读视图；`shipping_view=readonly` 即使由管理员打开也按本人过滤。管理员查其他人的单据使用正常管理链接。
- 飞书“按原申请确认”回调将原消息 ID 保留进持久化确认任务，完成后仅更新原库存确认卡片及已登记提醒卡片，不给新增管理员补发新卡片。缺 ID、快照读取失败或原消息过期时保留重试 / 核对，不能退回重新发送。重复点击有幂等保护；同单卡片更新按任务顺序执行并等待业务字段发布；已有审批实例后的重复确认不覆盖审批发放数量。
- 部分驳回复用 / 更新原申请人和处理人的卡片。多个驳回批次按顺序更新，避免旧重试把新版卡片覆盖。
- **物料管理、配货、发货的额外管理员成功回执全部取消**。保留原业务卡片、申请人必要通知以及配货 / 发货失败需核对提醒；按 2026-10-29 最新要求停用“物料管理任务需核对”管理员卡片，包括尚未发送和待重试的此类回执，业务错误记录及同步冲突仍保留；不要恢复“配货调整已完成”“发货信息已同步”“品类变更已完成”等额外绿卡片。

## 本地后台任务查看

- 系统工具的“后台任务”仅已启用的管理员可查看，API 同样鉴权。直接读取本地 jobs / outbox / effects 及校验、导入记录，不把任务监控写入飞书多维表格。
- 默认显示全部类型进行中任务，每 2 秒刷新；区分等待、执行、重试、失败和冲突，可搜索、按日期筛选、分页、查看结果及关联记录。业务处理完成不代表飞书同步 / 卡片通知已完成。
- 业务和 inbound Worker 使用独立短连接发布本地运行标记与进度；标记以 PostgreSQL backend 身份验证，进程退出后的旧标记不能被当作执行中。保持业务事务、幂等、通道顺序和失败记录；查看页面无重放、修改、取消或删除操作。
- 通讯录 contacts 是定时 / 按需刷新任务，显示上次完成时间及当时版本，不套用常驻服务两分钟心跳失效规则；常驻 Worker 单独计数。
- 自动刷新在页面隐藏时暂停、返回时恢复，手动暂停明确标识；网络失败保留上次数据并标明过期。详情同样刷新，不显示凭据。Worker 心跳是近期活动证据，不代替单条业务同步完成状态。

## 界面和附加功能

- 申领图片从虚拟机版本化文件读取，附件关联仍以 PostgreSQL 为准。来源文件首次补取后后台预备 WebP，令牌 / 本地摘要变化使用新文件；请求仍验证当前图片关联和款式可见性。业务 JSON 不缓存，图片操作不占业务 HTTP 线程池。
- 移除各页面重复的大标题说明栏，必填项红色 `*`，短时提示统一右上角红色浮层。
- 申请提交成功原文：**您的申请已提交，稍后将通过飞书同步申请信息。** 提交人取飞书身份，后端保存，不另显示可修改输入框。
- 物料管理新增“下单分装表生成”，仅管理员。单独选择本次生成日期，批量选择已核实库存的有效普通物料申请，自动仅提取品类定义为印刷物料的全部有效配货明细，不按“需要下单”过滤；排除取消、驳回、撤回、零量和失效关联。实际发放数量为正时优先，否则采用审批通过数量，缺字段才用申请数量。支持额外选择现有印刷规格与手填自定义品类 / 型号 / 语种 / 数量 / 用途 / 制作备注，可单独生成或与申请单合并。两表从同一批明细生成，下单按稳定规格及制作备注汇总、保留逐单用途数量；分装按申请单 / 额外用途分组，组内保留明细。用途较多时下单表续行，数量不丢失。两表逐批总数一致。
- 下单分装生成前核对来源指纹并保存 PostgreSQL 快照、幂等本地导出任务及历史；后台 inbound 在线程外业务事务执行 XLSX，文件在共享媒体下保存并进入既有备份。历史重下载读当时快照文件及 SHA256，不随申请变更重算。此功能为资料生成，不登记采购批次、不改库存 / 在途 / 审批、不触发通知；旧排期仍关闭。自定义条目仅存本次导出，不创建库存主数据或消耗额度。
- 发货模板保持附加功能，不额外创建数据库 / 飞书字段定义。按 2026-10-28 最新要求关闭物料管理中的发货排期页签和加载入口，旧地址跳转品类管理；配货与发货中的物料发货日历继续使用，不删除飞书原排期数据。
- Shipping Cost 按原货值比例分摊，货物单价最多两位小数，数量乘单价保留金额公式；总额允许合理尾差，PL 不因 INV 运费分摊而修改。

- 下单分装表生成默认只显示有印刷物料的申请，筛选可切换无印刷物料或全部。日历同时用蓝色 / 灰色数量区分两类；存在印刷关联核对警告的申请保留在印刷侧，避免静默隐藏异常。切换筛选不丢失已选申请。业务 Worker 的临时文件使用 shared/runtime-tmp（0700），保留 ProtectSystem=strict / ProtectHome=read-only，不开放默认 /tmp 或发布目录写权限。

- 下单 / 分装 Excel 使用用户提供《10月26日营销物料下单与分装.xlsx》的原始样式：等线字体、黑色细边框、白底下单表、分装申请浅色分组与用途纵向合并；列宽、默认 / 表头行高、主题、冻结和打印设置从去数据样式快照读取。仅扩展明细和分组，不附加自定义蓝色表头、页脚或打印缩放。原模板业务数据不进入 Git；导出结果记录模板来源 SHA256。旧文件保持原样，新生成使用当前模板。
