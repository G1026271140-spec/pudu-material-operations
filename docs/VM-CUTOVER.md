# 虚拟机完全替换说明 — V3.7.6

访问地址：https://materials.pudu.work/ 。企业文化衫专用入口为
https://materials.pudu.work/corporate-apparel 。两个入口均通过飞书登录。

## 数据流

普通申请、文化周边申请、企业文化衫申领，以及配货、补减库、品类和基础维度
管理，先在 PostgreSQL 的短事务中完成业务校验、库存/额度变更、审计和同步任务
保存。页面从 PostgreSQL 读取。网络调用不占用业务事务。

material_store.jobs 提供本地持久化业务任务；普通、文化、管理和卡片分别调度。
material_store.outbox_worker 将 create/update/delete 发布到对应飞书来源，并保留
失败重试、依赖等待与人工冲突状态。material_store.effects 独立发送/更新卡片。
消息使用稳定 UUID；超出去重窗口且结果不明的消息进入人工核对，避免再次发送。

现有飞书自动化仍可使用后台任务队列。legacy_bridge 将这些任务交给本地事务执行，
待本地业务、对应飞书同步和通知全部完成后，再标记旧队列任务完成。审批回写前
刷新相关申请、明细、库存和流水。两个 token 校验的回调地址保持原路径：
/api/pending-inventory-sync 与 /api/corporate-exchange-sync；回调先持久化再应答。
事件刷新遇到未同步本地变更会等待，不会拿较旧快照覆盖刚提交的操作。

## 服务与备份

- pudu-material-web：网页/API。
- pudu-material-outbox@ordinary、@cultural、@admin：飞书数据同步。
- pudu-material-business：四条本地业务调度通道。
- pudu-material-effects：持久化通知。
- pudu-material-card：飞书长连接、卡片回调与库存机器人。
- pudu-material-bridge：现有飞书工作流队列衔接、库存提醒调度。
- pudu-material-assets：全球之旅素材处理，保留原历史处理状态和轮询间隔。
- pudu-material-english：全球活动英文同步，保留原状态。
- pudu-material-backup.timer：每天北京时间 02:40。
- pudu-material-reconcile.timer：每天北京时间 03:00，以飞书为准全量校验。

数据库、图片、外部配置，以及扩展的配置和 JSON 状态均纳入私有备份。
原始下载素材保存在 shared/extensions/material-automation/downloads；Windows
已有归档文件保留在旧电脑，处理基线已迁移，不会重新初始化历史记录。
备份恢复必须在独立数据库验证所有表指纹和文件哈希，不得覆盖生产库。

管理员只读运行状态接口：GET /api/admin/runtime-status；需要管理员登录。
返回业务任务、通知、飞书同步状态计数及 worker 版本/心跳。

## V3.7.0 全部前端业务写入核对

正常操作以虚拟机 PostgreSQL 为准；HTTP 返回保存成功前，业务数据、审计和
outbox 必须在同一本地事务提交。后台 worker 再更新对应飞书表。飞书故障时
本地已保存的内容仍可供页面读取，未同步任务保留重试状态。

| 前端功能 | 本地入口 | 飞书更新方式 |
| --- | --- | --- |
| 普通物料申请、混合申请、文化周边申领 | submissions.submit_groups | ordinary/cultural outbox |
| 企业文化衫申领、HR 驳回和额度恢复 | jobs + DatabaseWriteClient | apparel_admin/primary outbox |
| 配货确认、配货编辑、撤回 | jobs + DatabaseWriteClient | create/update/delete outbox |
| 补库、减库及库存流水 | jobs + DatabaseWriteClient | admin outbox |
| 品类新增、编辑、删除、可选图片 | jobs + 本地 media | admin outbox，附件由 worker 上传 |
| 型号、语言、战区管理 | jobs + DatabaseWriteClient | admin outbox |
| 数据库工作台单元格编辑 | repository.patch_record | admin outbox |
| 飞书卡片操作及回调 | 持久化本地 jobs/inbound | 同样的事务及 outbox |

读取库存时，页面和业务事务共用关联记录 ID 对应的当前品类、型号、语种及战区
名称。仅改变业务读取视图，不改写导入原文，也不修改历史申请快照。关联缺失时
保留原文本，不进行模糊匹配，不另建库存行。

撤回同步允许飞书自动生成的部门及历史创建基线中未记录的双向回链，也允许同时
撤回的关联记录被飞书提前清理；其他人工字段变更仍进入冲突状态，避免误删。

每日北京时间 03:00（systemd OnCalendar 中显式指定 Asia/Shanghai），读取两个
飞书来源的全部 23 张表，以飞书值更新本地，包括手动修改和清空。日校验发现与
旧待同步写入不同的字段时，保留冲突审计并阻止旧任务再次覆盖校验结果；尚未取得
飞书 ID 的新建本地记录继续保留，等待同步。发货模板与发货排期维持现有附加功能。

本次验证：全部注册字段的 PostgreSQL 回读、六组关联维度改名、撤回自动字段及
真实人工冲突、日校验方向均纳入回归。只读生产对照 775 条普通库存、67 条文化
周边库存、215 条文化衫规格；774 个有效普通申请组合全部可匹配。独立恢复库禁止
真实飞书 HTTP，验证申请/驳回、配货/撤回、补减库、品类图片及维度修改，随后模拟
飞书运行 worker，28 个 outbox 完成、34 条通知无重复，生产业务写入为零。

## V3.7.2 导航及新型号产品线

配货工作台独立于物料管理；物料管理、配货工作台与数据库工作台仅出现在管理员的
“数据与系统工具”中，数据库接口继续由 require_admin 保护。配货/数据库不再
渲染在物料管理内部，原 URL 仍可访问。物料管理内的型号、语种、战区页归入
品类管理子导航，支持直接访问原子页面 URL 及浏览器前进后退。

移除物料管理、文化周边申领整块页头，以及申请页的规格预加载、基础信息说明，
配货页的库存复核副标题及列表说明/读取时间。三种申请完成页统一提示：
“您的申请已提交，稍后将通过飞书同步申请信息。”，不展示内部队列或数据库术语。

品类新增/编辑中的每个手填新型号均可独立关联产品线，可选择已有值或手动填写。
model_product_lines 随品类参数进入本地业务事务，新型号记录和物料关联及同步
outbox 一起提交；仅新建型号写入产品线，已有型号须在型号管理中修改。普通及
文化周边品类均有真实隔离 PostgreSQL 回归，禁止业务事务访问飞书 HTTP。

V3.7.3 将三项管理工具集中于“数据与系统工具”，所有现有表单必填星号统一为红色 RequiredMark 组件，涵盖普通、文化周边、企业文化衫、配货、管理及发货模板表单，保留原业务校验。


## V3.7.4 HR 企业文化衫管理

数据与系统工具新增 /management/corporate-apparel，仅启用的 HR / 管理员可见，
后端 /api/hr/corporate-apparel/* 独立校验权限，普通销售、停用账号无权读写。
业务数据只操作行政源表 tbledtC3RafsHNh0 的文化衫行，不开放其他表的数据库编辑。

行政源表增加四个字段：申领款式编号、申领显示名称、申领页显示、每人累计领取上限；
迁移脚本 deployment/postgres/009_apparel_catalog_fields.sql 对应稳定字段 ID，注册
全部 362 个字段。每日 03:00 校验包含这些设置，继续以飞书为准。

管理界面支持款式新增/改名/下架/删除、每个尺码的新增/编辑/删除、原始库存和入库纠正、
编码、备注、图片和个人累计上限。系统兑换、表格兑换和计算库存只读。存在领取历史
或兑换数量的规格禁止删除，提示下架；历史申请保留款式稳定编号，不随改名丢失。

正常保存为同一本地事务中的行政源数据、审计及 outbox；图片先落本地，worker 上传。
申领页直接读取本地行政源表，新款式/尺码无需等待飞书同步连接器生成中间表记录。
现有五款继续使用既有用户累计字段，新款式按已发放明细和申请人累计，HR 驳回恢复
库存和额度。配置较低额度时已领记录保留，后续申请按新上限校验。

待同步新记录的连续编辑也递增乐观版本并锁定 outbox，避免两个 HR 相互覆盖；
新上传图片须属于当前操作人，已关联图片允许其他有权限 HR 编辑。
