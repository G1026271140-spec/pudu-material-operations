# 物料发货日历

入口：后台编辑 → 配货与发货 → 物料发货日历。
同页可切换“配货工作台”和“物料发货日历”；原配货和日历链接均保持可用，浏览器前进、后退和刷新会保留对应子页面。
路由：`/management/shipping-calendar`。企业内已登录申请人可以只读查看本人的单据；已启用管理员可查看全部并编辑。
非管理员只显示发货日历，不开放配货页签。列表和图片均在服务端验证原申请人 open_id；姓名、提交人和客户端查询参数不能扩大范围。

## 展示口径

数据直接读取虚拟机 PostgreSQL 申请单和申请明细；不用页面业务缓存。
仅展示普通物料申请、库存审查状态为“已核实库存”，并排除撤回、驳回、取消中的单据。
未发货和已发货分两列，以原申请单的“是否发货”复选框区分，不能由有无运单号推断。
日历按北京时间计算“今天”；可切换计划发货日、要求到达开始日。
缺少当前依据日期的申请单保留在未设置日期分组；整月视图同时显示这些单据。
支持全部日期及单号、申请人、物料、物流信息搜索。
卡片同时显示发货日与到达日，详情显示全部申请明细和收件信息。
超过计划发货日但未发货的单据显示提示；已发货单据不显示逾期提示。

## 保存、自动发货和同步

管理员和中台可批量暂存日期、物流文字和图片。点击“统一提交修改”确认原文为：**发货信息即将同步给申请人，请确定提交**。取消保留草稿。确认后同一短 SQL 事务保存本地字段、审计、幂等结果和 ordinary outbox，页面立即读取本地结果；事务内不调用飞书。旧单笔保存接口已停用。

是否发货在启用自动规则后只读。按 2026-10-29 最新规则，状态与通知独立判断：

1. 原生审批 `APPROVED`、审批表单申请单号与当前单一致，就自动勾选已发货。物流内容、源表“已发放”和明细完整回写不作为勾选的附加条件。
2. 原生审批通过，并且物流文字去掉首尾空格后非空，或至少一张有效图片，才给原申请人发货卡片。没有物流信息时保留“已发货 / 待填写物流信息”，之后补填再通知。
3. 状态更新只修改“是否发货”，不审批、不补扣库存、不更改明细、实际发放数量或原审批表单。明细异常继续单独核对。

先在 PostgreSQL 保存状态、审计和 outbox，后台同步飞书；申请人通知等待相关数据发布完成。历史已通过申请可补齐发货勾选，保持历史通知基线，不因规则调整批量补发旧通知。源审批已驳回 / 撤回的申请从日历隐藏，并在后端拒绝发货编辑；更换审批实例后不会沿用旧实例的驳回缓存。

应用变更先作用于 PostgreSQL；飞书手工变化及审批回写由已启用的申请单变更工作流通知 `/api/pending-inventory-sync`，1 秒后合并刷新。bridge 同时每 15 秒完整读取申请单、明细、库存、流水补漏，并查询待审批实例；不依赖每天的核对。源端和网络时间另计，15 秒是补偿启动间隔，不是最长完成时延。页面每 3 秒检查含审批元数据的数据库版本，更新只读页面并保留编辑中的草稿。

图片先持久化共享媒体及本地媒体表，再由 outbox 上传到飞书；支持 PNG/JPEG/WebP，单张 6 MB、2400 万像素、每单 12 张。新增图片验证当前上传人，已有图片只能保留本单附件。服务端按原申请人 / 管理员 / 中台验证读取和编辑权限，不能跨单注入附件。上传后的远端 token 与本地图片 ID 做一致化，避免重复通知。

网页提交按服务器最后成功事务写本次字段；幂等重试不重复执行，真实源冲突仍须核对。修改日期时同步原申请单、申请明细、下单明细及关联批次；通知等待相关 outbox。发货编辑不改变申请数量、不审批、不扣库。每天 03:00 Asia/Shanghai 仍完整核对 23 表，以飞书为准。

通知为原申请人的 Card 2.0，标题“您的物料申请已发货”；已经通知过的申请变更日期，发送“物料发货时间变更通知”卡片。按钮使用 owner-only 只读链接。收件人严格取申请人 open_id，不接受前端指定。未尝试的旧通知可被最新内容替代；消息超时使用同一 UUID，曾尝试但内容变化的旧任务保留核对，避免重发旧物流。任务成功后才显示已通知。物料管理、配货和发货的额外管理员成功回执继续取消。

## 启用与运维

统一发布代码后，先通过现有 `material_store.inbound.refresh` 刷新上述四表，再执行：

```bash
cd /home/gaohongyuan1/pudu-materials-operation/source
/home/gaohongyuan1/pudu-materials-operation/venv/bin/python -m material_store.auto_shipping --activate
```

启用建立历史基线，不写业务字段、不发送旧通知；可使用 `--seed-native <受限审批审计文件>` 导入已读取的原生实例结果。启用标记和每单观察状态位于 `material_ops.documents`，前缀 `automatic-shipping:`。桥接服务每次成功补偿的完成时间、用时及统计保存在 `automatic-shipping-poll`，失败会写 systemd 日志。无新增 systemd 服务或业务字段 / SQL 迁移。

历史审批与库存异常应单独核对，不得通过重放整张申请或更改明细为“已发放”来绕过规则。回退按统一发布流程；若需停用自动规则，受控删除 `automatic-shipping:enabled` 标记并保留每单观察记录、outbox、effects 和审计；未发送自动通知会在最后校验时停止。停用后页面回到原手工复选框，必须同步业务决策。
