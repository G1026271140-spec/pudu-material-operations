# 申请记录、额度与人员权限

入口位于“数据与系统工具”。

## 申请记录与额度

路由 `/management/request-history`，读取接口 `/api/request-history?scope=mine|all`。

| 登录身份 | 记录范围 | 企业文化衫驳回 |
| --- | --- | --- |
| 普通申请人 | 本人普通物料、文化周边、企业文化衫 | 不允许 |
| 已启用 HR | 全公司文化周边和企业文化衫；不返回普通物料 | 允许 |
| 已启用管理员 | 可切换本人和全部三种类型；管理员角色优先 | 允许 |

账号归属通过原申请单“申请人”的 open_id 判断，姓名和提交人不能扩大范围。
未登录不能访问；普通用户请求 scope=all 返回 403。
历史明细按原记录关系关联，存在明确关系时不按单号猜测，避免串单。
本地保留的删除记录作为“已撤回 / 已删除”只读历史显示。
支持按类型、状态、日期、单号、人员、部门和物料搜索及分页，详情显示原申请明细与发货信息。

“我的企业文化衫额度”始终展示当前登录人的所有源表文化衫款式。
额度与现有实际申领校验口径一致：原五类使用用户权限表中的累计字段，新增款式使用系统有效发放明细累计；
领取上限和是否开放取行政源表当前配置。额度只读，角色修改不重置累计字段。

## 企业文化衫驳回

接口 `/api/request-history/reject-apparel`，只有已启用 HR 和管理员可操作，必须确认。
仅处理已发放的企业文化衫，不能借此操作普通物料或文化周边。
复用原有 `corporate-apparel-reject:<申请单号>` 持久化任务与卡片操作的幂等键；
本地业务事务恢复行政库存、个人额度和明细发放状态，后由 outbox 同步飞书。
对同一申请单重复点击或页面、卡片同时操作不重复恢复。

通知复用现有申请人和 HR 卡片构造器和原消息 ID，优先更新原卡片。
卡片消息任务等待该次变更的 outbox 完成，包括尚未发布且被合并的 create 任务。
原消息被删除（230031）时，使用相同效果 UUID 补发结果卡片。
只有全部卡片实际更新成功，才把“文化周边通知状态”写为“驳回已通知”；
失败不冒充成功，页面按实际效果任务显示待同步、已更新或需核对。
业务写入、消息重试均不在 SQL 事务内发起网络请求。

## 用户权限管理

路由 `/management/user-permissions`，GET/POST `/api/admin/user-permissions`，仅已启用管理员。
公司人员先读取数据库以便即时显示；打开权限管理页、点击“实时刷新通讯录”、页面可见且未编辑时每分钟，均会提交实时通讯录刷新任务。
后台 worker 从飞书完整读取部门及成员，成功后原子更新数据库，页面自动更新人员列表。
同一时刻的刷新请求合并为一笔，刷新失败保留原数据并明确提示，不把旧数据当成刷新成功。
每天 03:10 的完整刷新继续保留。
搜索姓名和部门、筛选角色，全部人员可分页查看；没有单独配置的人员标明默认销售。

沿用用户权限表 `tblytA4DHQVbJiIJ` 的“用户账号、角色、是否启用”字段，
角色选项来自当前字段定义（管理员、销售、区域市场经理、HR）。
保存后先更新 PostgreSQL 和审计、幂等记录、admin lane outbox，再同步飞书。
新人员以用户账号查重，飞书自动生成用户编号；不使用自动编号作为前端写入标识。
同一账号的重复权限记录按已启用记录的角色并集合并显示，任一已启用记录代表账号启用；全停用时保留角色设置但不授予权限。
登录身份角色也按相同规则取并集。编辑时同时校验全部重复记录的版本，并统一更新每条记录的角色和启用状态。
原有额度累计和其他字段逐条保留，不删除记录、不合并累计字段；版本或同步冲突需刷新核对。
至少保留一名已启用管理员，修改本人角色后刷新当前权限。
每天 03:00 的飞书优先校验继续覆盖权限字段。
