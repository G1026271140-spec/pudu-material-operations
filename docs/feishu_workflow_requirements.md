# 飞书 aPaaS 物料申请与库存流程需求

本文档描述将当前 Streamlit 物料库存应用迁移到飞书 aPaaS 后，需要配置的具体流程需求。

## 一、业务目标

当前应用用于管理市场物料库存。销售发起物料申请后，市场营销部审批并根据实际情况发放物料，最终把实际发放数量写入库存流水和当前库存。

迁移到飞书 aPaaS 后，需要实现：

1. 销售在线提交物料申请。
2. 一张申请可包含多条物料明细。
3. 市场营销部收到待审批提醒。
4. 市场可审批通过、驳回、调整审批数量或标记缺货。
5. 市场按实际发放数量批量出库。
6. 库存不足时系统拦截，不允许扣成负库存。
7. 所有库存变化必须生成库存流水。
8. 支持采购入库、盘点调整、撤回冲销。
9. 销售只能查看自己的申请，市场可查看和处理全部申请。

## 二、数据对象

流程需要操作 5 个数据对象：

| 数据对象 | 用途 |
|---|---|
| 物料主数据 | 保存物料编码、品类、型号、语种、当前库存、启用状态 |
| 物料申请单 | 保存销售一次申请的主信息 |
| 申请明细 | 保存每张申请单下的物料明细 |
| 库存流水 | 保存所有入库、出库、盘点、撤回冲销记录 |
| 库存批量操作 | 保存批量发放、批量入库、批量撤回的执行结果 |

## 三、统一云函数

免费版只使用一个云函数：

```text
material_inventory_workflow
```

所有流程通过不同 `action` 调用该函数：

| action | 用途 |
|---|---|
| submit_request | 销售提交物料申请 |
| approve_request | 市场审批通过 |
| reject_request | 市场驳回申请 |
| batch_issue | 市场批量实际发放 |
| inventory_change | 采购入库/盘点调整 |
| revert_ledger | 撤回库存流水 |

## 四、状态定义

### 1. 物料申请单状态

| 状态 | 含义 |
|---|---|
| 草稿 | 销售已创建但未提交 |
| 待审批 | 销售已提交，等待市场审批 |
| 审批中 | 市场正在处理，可选状态 |
| 已驳回 | 市场驳回 |
| 待发放 | 市场审批通过，等待实际发放 |
| 部分发放 | 部分明细已发放，部分未完成 |
| 已发放 | 所有有效明细已完成发放 |
| 已取消 | 申请取消 |

### 2. 申请明细状态

| 状态 | 含义 |
|---|---|
| 待审批 | 随申请单提交，等待审批 |
| 待发放 | 审批通过，等待市场发放 |
| 已发放 | 已生成出库流水 |
| 部分发放 | 实际发放数量小于审批通过数量 |
| 缺货 | 库存不足，无法发放 |
| 取消 | 明细取消 |

### 3. 库存流水状态

| 状态 | 含义 |
|---|---|
| 有效 | 正常生效的库存流水 |
| 已撤回 | 原流水已被撤回 |
| 冲销记录 | 撤回时生成的反向流水 |

## 五、流程 1：销售创建草稿

### 触发方式

销售打开“销售物料申请”页面，点击“新建申请”或填写表单。

### 参与角色

销售。

### 前置条件

- 销售已登录飞书。
- 物料主数据已存在且启用。

### 页面字段

申请单：

- 申请人
- 申请部门/区域
- 业务类型
- 用途/活动
- 期望发放日期

申请明细：

- 物料编码/物料
- 申请数量
- 提交时库存快照

### 系统动作

1. 创建 `物料申请单`。
2. 默认 `审批状态 = 草稿`。
3. 创建一条或多条 `申请明细`。
4. 默认 `明细状态 = 待审批` 或暂存状态。

### 校验规则

- 用途/活动必填。
- 期望发放日期必填。
- 至少添加一条物料明细。
- 申请数量必须大于 0。
- 物料必须是启用状态。
- 同一申请单内同一物料不建议重复；若重复，系统应提示合并数量。

### 验收标准

- 销售可以保存草稿。
- 草稿不会触发市场审批提醒。
- 销售可继续编辑本人草稿。

## 六、流程 2：销售提交审批

### 触发方式

销售点击“提交审批”按钮。

### 调用云函数

```json
{
  "action": "submit_request",
  "request_no": "REQ-20260702-0001",
  "operator": "当前用户"
}
```

### 系统动作

1. 校验申请单必填项。
2. 校验至少一条申请明细。
3. 校验所有明细申请数量大于 0。
4. 读取每条物料的当前库存，写入 `提交时库存快照`。
5. 将申请单状态改为 `待审批`。
6. 将申请明细状态改为 `待审批`。
7. 写入提交时间。
8. 向市场营销部群或市场负责人推送待审批消息。

### 校验规则

- 已提交、已驳回、待发放、已发放的申请不能重复提交。
- 停用物料不能提交。
- 申请数量必须是正整数。

### 异常处理

- 如果物料不存在，返回错误：`未找到物料`。
- 如果物料停用，返回错误：`物料已停用`。
- 如果无明细，返回错误：`请至少添加一条物料明细`。

### 验收标准

- 提交后销售不可随意修改明细。
- 市场人员能收到待审批提醒。
- 申请单进入市场待审批列表。

## 七、流程 3：市场审批通过

### 触发方式

市场在“市场审批工作台”点击“通过”。

### 调用云函数

```json
{
  "action": "approve_request",
  "request_no": "REQ-20260702-0001",
  "operator": "当前用户",
  "comment": "同意发放"
}
```

### 系统动作

1. 校验当前用户属于市场角色。
2. 查询申请单和申请明细。
3. 默认 `审批通过数量 = 申请数量`。
4. 如果市场修改了审批通过数量，保存市场修改值。
5. 将申请单状态改为 `待发放`。
6. 将有效申请明细状态改为 `待发放`。
7. 写入市场负责人和审批时间。
8. 推送待发放提醒给市场发放人员。

### 校验规则

- 只有 `待审批` 或 `审批中` 状态允许审批通过。
- 审批通过数量不能小于 0。
- 审批通过数量不能大于申请数量，除非市场主管权限允许超发审批。
- 若当前库存不足，可提示库存不足，但是否允许审批通过由业务决定；真正的库存不足拦截发生在实际发放时。

### 异常处理

- 如果申请单状态不是待审批，返回错误：`当前状态不可审批`。
- 如果审批数量不合法，返回错误：`审批通过数量不能大于申请数量`。

### 验收标准

- 审批通过后申请进入待发放列表。
- 销售可看到申请已通过或待发放。
- 不在审批阶段直接扣库存。

## 八、流程 4：市场驳回申请

### 触发方式

市场在“市场审批工作台”点击“驳回”。

### 调用云函数

```json
{
  "action": "reject_request",
  "request_no": "REQ-20260702-0001",
  "operator": "当前用户",
  "comment": "用途不明确，请补充说明"
}
```

### 系统动作

1. 校验市场权限。
2. 将申请单状态改为 `已驳回`。
3. 将申请明细状态改为 `取消` 或保持 `待审批` 但不再可发放。
4. 写入审批意见。
5. 推送驳回消息给申请人。

### 校验规则

- 驳回意见必填。
- 已发放申请不能驳回。

### 验收标准

- 销售能看到驳回原因。
- 驳回申请不会进入待发放列表。
- 不产生库存流水。

## 九、流程 5：市场实际发放

### 触发方式

市场在“市场发放工作台”勾选一条或多条待发放明细，填写实际发放数量，点击“批量发放”。

### 调用云函数

```json
{
  "action": "batch_issue",
  "line_nos": [
    "LINE-20260702-0001",
    "LINE-20260702-0002"
  ],
  "operator": "当前用户"
}
```

### 系统动作

对每条申请明细逐条处理：

1. 查询申请明细、申请单和物料主数据。
2. 校验明细状态为 `待发放`。
3. 校验实际发放数量大于 0。
4. 校验实际发放数量不大于审批通过数量。
5. 校验明细尚未生成出库流水。
6. 重新读取物料当前库存。
7. 如果当前库存不足，则该行失败，不扣库存。
8. 如果库存充足，生成一条 `库存流水`：
   - 流水类型：`销售领用出库`
   - 数量变化：`-实际发放数量`
   - 变更前库存：当前库存
   - 变更后库存：当前库存 - 实际发放数量
   - 幂等键：`issue:明细编号`
9. 更新物料主数据 `当前库存`。
10. 写回申请明细：
    - 出库流水编号
    - 发放人
    - 发放时间
    - 明细状态
11. 根据所有明细状态更新申请单状态：
    - 全部完成：`已发放`
    - 部分完成：`部分发放`

### 校验规则

- 实际发放数量必须大于 0。
- 实际发放数量不能大于审批通过数量。
- 库存不足时必须拦截。
- 已经有出库流水编号的明细不能再次发放。
- 同一个幂等键不能重复生成流水。

### 异常处理

- 单条失败不影响其他选中明细继续处理。
- 批量结果需要返回逐条成功/失败原因。
- 库存不足行可以标记为 `缺货`，或保留 `待发放` 并写缺货说明。

### 验收标准

- 批量发放成功后，库存减少。
- 每条成功发放明细都有对应库存流水。
- 库存不足不会扣成负数。
- 重复点击按钮不会重复扣库存。

## 十、流程 6：采购入库

### 触发方式

市场在“库存管理”页面点击“采购入库”。

### 调用云函数

```json
{
  "action": "inventory_change",
  "material_code": "MAT-0001",
  "ledger_type": "采购入库",
  "quantity_delta": 100,
  "idempotency_key": "purchase:MAT-0001:20260702:001",
  "operator": "当前用户",
  "note": "新采购到货"
}
```

### 系统动作

1. 查询物料主数据。
2. 校验物料启用。
3. 读取当前库存。
4. 生成入库流水。
5. 更新当前库存。

### 校验规则

- 入库数量必须大于 0。
- 幂等键不能重复。
- 停用物料不能入库，除非管理员允许。

### 验收标准

- 入库后当前库存增加。
- 库存流水中有入库记录。

## 十一、流程 7：盘点调整

### 触发方式

市场主管或管理员在库存管理页面点击“盘点调整”。

### 调用云函数

```json
{
  "action": "inventory_change",
  "material_code": "MAT-0001",
  "ledger_type": "盘点调整",
  "quantity_delta": -3,
  "idempotency_key": "adjust:MAT-0001:20260702:001",
  "operator": "当前用户",
  "note": "盘点差异调整"
}
```

### 系统动作

1. 查询物料。
2. 读取当前库存。
3. 计算调整后库存。
4. 若调整后库存小于 0，则拦截。
5. 生成盘点调整流水。
6. 更新当前库存。

### 校验规则

- 盘点调整必须填写备注原因。
- 普通销售不能执行盘点调整。

### 验收标准

- 盘点调整有完整流水。
- 备注可追溯。

## 十二、流程 8：撤回/冲销库存流水

### 触发方式

市场主管或管理员在“库存流水”页面点击“撤回流水”。

### 调用云函数

```json
{
  "action": "revert_ledger",
  "ledger_no": "TX-20260702-0001",
  "operator": "当前用户",
  "note": "误操作撤回"
}
```

### 系统动作

1. 查询原流水。
2. 校验原流水状态为 `有效`。
3. 原流水状态改为 `已撤回`。
4. 新增一条反向流水：
   - 流水类型：`撤回冲销`
   - 数量变化：`-原流水数量变化`
   - 原流水编号：原流水编号
   - 操作状态：`冲销记录`
5. 更新物料当前库存。

### 校验规则

- 已撤回流水不能再次撤回。
- 冲销记录不能再撤回。
- 撤回必须填写原因。

### 验收标准

- 不删除历史流水。
- 库存被正确反向恢复。
- 原流水和冲销流水可以互相关联。

## 十三、流程 9：库存预警

### 触发方式

物料主数据的当前库存发生变化后。

### 系统动作

1. 判断当前库存是否小于等于库存下限。
2. 若小于等于库存下限，推送低库存提醒给市场主管。
3. 若当前库存小于 0，推送异常库存提醒。

### 校验规则

- 当前库存不能被业务函数扣成负数。
- 负库存只应出现在历史导入、手工异常或管理员特殊调整后。

### 验收标准

- 低库存物料可被市场及时发现。

## 十四、权限需求

### 销售

- 可创建申请单和申请明细。
- 可查看本人申请。
- 可编辑本人草稿。
- 不可审批。
- 不可发放。
- 不可修改物料主数据当前库存。
- 不可新增或修改库存流水。

### 市场专员

- 可查看所有申请。
- 可审批申请。
- 可填写实际发放数量。
- 可批量发放。
- 可采购入库。
- 可查看库存流水。
- 不可删除库存流水。

### 市场主管

- 拥有市场专员权限。
- 可执行盘点调整。
- 可撤回/冲销流水。
- 可处理异常库存。

### 管理员

- 可维护所有数据对象、页面、流程、权限、云函数。

## 十五、整体验收场景

### 场景 1：正常申请与发放

1. 销售提交 2 条物料申请。
2. 市场审批通过。
3. 市场填写实际发放数量。
4. 点击批量发放。
5. 系统生成 2 条出库流水。
6. 物料当前库存减少。
7. 申请单状态变为已发放。

### 场景 2：库存不足

1. 物料当前库存为 3。
2. 市场实际发放数量填 5。
3. 点击批量发放。
4. 系统返回库存不足。
5. 不生成库存流水。
6. 当前库存仍为 3。

### 场景 3：重复点击发放

1. 市场对同一明细点击批量发放。
2. 第一次成功生成流水。
3. 第二次再次点击。
4. 系统识别已有出库流水或幂等键重复。
5. 不重复扣库存。

### 场景 4：采购入库

1. 市场对某物料入库 100。
2. 系统生成采购入库流水。
3. 当前库存增加 100。

### 场景 5：撤回流水

1. 市场主管撤回一条误操作流水。
2. 系统新增反向冲销流水。
3. 原流水标记已撤回。
4. 物料库存恢复。
