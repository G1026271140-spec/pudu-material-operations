# 验收、已知边界与签收

## 本次打包验证范围

实时结果见 `04-verification`，包括源码版本、Python 测试、语法检查、安装器嵌入载荷、ZIP CRC、manifest SHA-256 和已知本机凭据匹配检查。秘密扫描不等于完整 DLP 审计；源码仍含内部表定位符与产品资产，禁止公开。

本次不改变生产配置/业务数据，不在新电脑执行安装、不切域名、不创建真实测试申请。因此“压缩包有效”不等于“新环境已通过生产验收”。当前 health 正常也仅说明服务存活。

## 新环境业务验收（与业务负责人共同执行）

- [ ] 正确企业用户能登录，外企业身份被拒；30 天会话、飞书工作台二次打开符合预期。
- [ ] 申请人默认登录人、可更换；提交人不可篡改；新用户显示/登记销售规则正确。
- [ ] 普通、文化周边、独立企业文化衫三个入口和中英切换可用。
- [ ] 普通目录、完整管理员/区域经理目录、停启/显示控制、已删除明细过滤正确；非管理员不能调用管理 API。
- [ ] 企业文化衫尺码只提供可领库存，POLO 多数量/多明细可用，共用个人额度及超限驳回正确。
- [ ] 指定一条测试申请的“已提交”回执 → 入队一次 → 最终申请/明细写入 → 管理员或 HR 通知完成。
- [ ] 配货列表从本机 SQLite 快速读取，原待核实单不丢；单条完成不移除其他单据；卡片动作同链路。
- [ ] 编辑/分装/按原申请发放/保存核实时间后，申请、明细、卡片、配货状态一致。
- [ ] 下单仅限印刷物料，在途数量正确；取消的下单二次确认和下单表功能不恢复。
- [ ] 申领驳回/申请撤回的库存、累计份额、保留记录与通知符合既有规则；失败任务按来源告警，不重复扣库存。
- [ ] 正常/重试/幂等检查点任务处理完成，机器人对申请人不可用不阻断管理员/HR 通知。
- [ ] Base 两条同步流程确实触发新节点，份额自动增量/定时补偿及缓存热发布验证通过。
- [ ] 发货模板 INV 的 Shipping Cost、总值不变、货物分摊与运费超值拦截正确。
- [ ] 素材整理/英文活动同步在各自源表以测试范围验证，无重复历史回写。
- [ ] 日志、备份、监控和恢复负责人明确；停机/断网/进程重启恢复验证；旧机器后台任务全部退出。

测试申请必须由业务负责人指定可逆测试数据和接收人，完成后按既有规则恢复/清理，不能自行生成真实申请或向全员群发送测试通知。

## 当前移交应知事项

1. 当前正式版本为 V3.4.5；来源提交及各 Runner SHA 写在快照中。缓存 Runner 提交领先不必然意味着代码版本不同，应查看具体 diff，当前已确认差异仅页面缓存。
2. 依赖策略：Python requirements 使用范围而非完整锁定；frontend 有 package-lock。包内保存本机 pip freeze 作为排障参考，不替代跨 Python/平台可移植的约束文件。
3. 旧 README / DEPLOYMENT / 部分历史文档含过时部署方式；交接包做显著提示。源码保留业务复用模块，不自行清除历史函数。
4. 现有原安装器内含业务缓存，因此未直接分发原 EXE；交接安装器从清理后的源快照重新生成。不得拿普通交接 ZIP 当作全量灾备。
5. 两个未提交的 LeadSubmission 前端文件单独保留，未发现被正式入口引用；不发布为已完成功能。另有外部 Lead Intake 任务需单独交接。
6. T300/CC1 新源模型演示放在可选附件，尚未替换当前应用模型。不要把可选模型当作已上线内容。转换说明中包含 CC1 两个零件未定义颜色的近似处理。
7. 域名所有权、公司 GitHub 归属、飞书应用管理人、长期运行主机归属与备份策略仍需数字化运营正式确认。本次没有代为转移这些账号所有权。
8. 交接副本另外将 `app.py` 的历史页面硬编码默认密码替换为明确占位值，并同步相关默认值测试。正式运行源码未修改。所有交接副本差异和原文件 SHA-256 均列入验证目录；旧页面若还需要使用，必须配置独立强密码，不能依赖默认值。
9. 清理副本的管理员/部署启动器测试通过（37 项）。另一次无缓存探测中 45 项通过、3 项登录集成测试因读取被排除的通讯录/页面缓存而失败，这一依赖已记录；不宣称本包在缺少配置和业务快照的新机上完整测试通过。先恢复授权快照或补隔离的合成测试夹具，再运行相关集成测试。
