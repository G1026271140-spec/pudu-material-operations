# 系统说明

## 1. 正式架构

用户浏览器/飞书工作台 → HTTPS 域名 → Cloudflare Named Tunnel → 部署主机 `127.0.0.1:8501` → FastAPI（`request_web.api:api`）。FastAPI 同时提供 React 构建后的页面、图片/模型和 API。

业务事实数据保存在飞书多维表格；JSON/图片快照用于加速。配货待核实记录及本地动作存入同机 SQLite，后台写入任务进入飞书队列，由 Windows Worker 执行。飞书卡片也会影响配货流程，不能只迁移网页而遗漏 Worker、回调和 SQLite 状态。

生产机器无需运行 Vite 开发服务器，已有 `request_web/frontend/dist`。构建前端才需要 Node.js/npm；具体依赖版本以 `package-lock.json` 为准。

## 4. 必须保留的业务边界

- 登录验证应用所属企业 tenant，不是只比较公司名称文字；须使用深圳市普渡对应的自建应用。会话为每人/浏览器独立的 30 天签名 Cookie，域名变化或 App Secret 轮换可能导致重新登录。
- 提交人来自登录身份，不可修改；申请人默认同提交人，可手动选择。权限判定必须由后端完成。
- 物料管理只允许启用的管理员；区域市场经理可看完整申领目录，但不因此获得物料管理权限。已删除的物料组合即使管理员也不可重新显示。
- 管理员申领范围不按“是否在申领页显示”及启停状态过滤；普通申请按既有规则过滤。
- 文化周边独立页按品类“是否在申领页显示”和库存“是否可以申领”共同控制。
- 企业文化衫与文化周边的 POLO/夹克共用个人累计份额；其余三个服装品类每人最多一件。新人员按当前规则登记启用销售权限。历史兑换核对按现有累计与来源累计取较大值，不能简单清零覆盖人工增量。
- 仅印刷物料需要下单；周边礼品和文化周边默认不下单。保留下单和在途库存，不恢复已取消的二次下单汇总确认/下单表下载。
- 配货可分装同品类型号/语种组合，以原申请数量为参考，分装总量允许增加或减少。未完成配货的其他申请不能因一条完成而从列表丢失。
- 物料明细通知使用表格；机器人对申请人不可用时跳过该人，不得阻断管理员/HR 通知和业务完成。
- 额度超限按驳回流程，不扣库存；失败/重试告警按来源路由到管理员或 HR，不能无限把业务拒绝当瞬时异常重试。
- 发货 INV 运费默认 100 美元，从货值中扣出而非叠加；运费超过货物原总值时需拦截提示。

详尽条件以当前代码与测试为准，以上是迁移和改造最容易误改的边界，不是替代代码的完整需求规格。
