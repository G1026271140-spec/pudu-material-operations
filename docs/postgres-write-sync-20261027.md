# V3.6.4 本地申请与飞书同步

本阶段将普通物料和文化周边申请先写入 PostgreSQL，同事务记录 outbox，HTTP 返回单号和本地保存状态。申请单、明细、文化库存和额度在飞书不可达时仍可完整提交或完整回滚；失败重试保留同一业务身份。

## 实现与验证依据

- 来源仍为 23 张表、358 个字段，初始 5,452 条业务记录。
- 普通申请和文化周边由独立通道发布；同一申请标识、人员权限、文化额度和库存用数据库锁协调，单号由每日计数器分配。
- 独立恢复库同时执行 5 笔普通申请和 2 笔文化周边申请，7 个单号唯一；重复提交不重复创建，不重复扣库或累计额度；同一标识变更内容及超过额度均拒绝。业务提交 HTTP 调用数为 0。
- Worker 按申请单、明细、流水的依赖顺序发布；远端创建后、本地完成前的失败通过业务幂等字段查重恢复。记录版本和租约控制旧任务，远端人工修改会转为冲突。
- 使用既有测试申请的备注完成真实飞书更新及两端读回，随后恢复原值；两条同步任务已完成。
- 完整回归 852 passed、5 skipped、21 subtests passed；TypeScript/Vite 构建与发布一致性检查通过。

## 每日校验

`pudu-material-reconcile.timer` 在北京时间 03:00 运行。全表读取和 schema 核对全部完成后，再以事务应用飞书当前值；保留字段级审计和软删除记录，取消可覆盖已采纳飞书值的旧任务。未取得飞书 ID 的本地新记录保留。

校验与发布任务使用会话锁协调，不在数据库事务中等待飞书 HTTP。普通页面读取可继续；需要提交的短事务在校验结束后继续。

2026-10-27 的首次全量实跑：23 表，更新 35 条、创建 0、删除 0、冲突 0。结果保存在虚拟机 `shared/pg-reconciliation-acceptance-20261027.json`。

## 备份与恢复

每日北京时间 02:40 的 `pudu-material-backup.timer` 保存 PostgreSQL custom dump、媒体及外置配置，生成 SHA-256 清单；目录和文件仅运行账户可读。凭据和业务备份不加入 Git。

已将当前 PostgreSQL dump 恢复到独立验证库，逐表比较记录键、远端 ID、原始字段、版本和状态的内容摘要，23 表、5,452 条记录一致，同时核对 outbox、审计、媒体、导入记录和文档数量。独立验证库已清理。上线后的验收记录与备份以虚拟机报告为准。

恢复时先停止 Web 和三个 outbox 服务，将 dump 恢复到新库并验证摘要，恢复对应媒体及外置配置，切换应用 DSN 后再启服务。禁止用旧库覆盖仍有本地未同步修改的库；回退应用 release 时保留数据库和 outbox。

## 发货模板金额

根据 2026-10-27 新增要求，Shipping Cost 按原货值比例从货物中扣出，每项导出单价先保留两位小数，金额由数量乘单价计算；在能够改善总额的情况下调整整分单价，允许无法消除的小额尾差。发票保留公式，PL 不含 Shipping Cost。目标总额在页面明确注明舍入尾差，物料主数据单价不受导出影响。

## 部署开关

```text
PUDU_DATA_SOURCE=postgresql
PUDU_DATABASE_DSN=dbname=pudu_materials
PUDU_DB_EDITOR_ENABLED=1
PUDU_BUSINESS_WRITES_ENABLED=1
PUDU_OUTBOX_WORKER_ENABLED=1
PUDU_WEB_READ_ONLY=1
```

本阶段的业务写入白名单为普通申请、文化周边申请及只生成文件的发货模板接口；管理员表格按字段权限编辑。其他原有审批、配货、补库、品类增删及行政文化衫兑换写入仍需通过各自后续迁移验收，不能仅移除全局只读保护就宣称已迁移。三个同步服务为 `pudu-material-outbox@ordinary`、`@cultural`、`@admin`，原飞书 Submission Worker 不与本地 outbox 混用。

线上浏览器已提交测试申请 REQ-20261027-001，标题及用途注明请勿配货；申请单与 1 条明细均由本地保存并同步至飞书，单号、数量和父子关联已两端读回核对。此验收覆盖申请保存与数据同步；审批、通知、配货等流程不在本次端到端验收范围。
