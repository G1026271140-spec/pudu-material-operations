# 飞书 aPaaS 物料申请与库存系统实施方案

本文档把当前 Streamlit 物料库存应用迁移为飞书 aPaaS 应用的第一版落地方案。目标不是只做一张表，而是做一个具备页面、权限、按钮、校验、库存不足拦截、批量处理和消息推送的业务应用。

## 结论

建议采用：

- 飞书 aPaaS 数据对象作为主业务数据库。
- 飞书 aPaaS 页面作为销售和市场部的操作入口。
- 飞书 aPaaS 流程承接审批、状态流转和通知。
- 飞书 aPaaS 云函数承接库存写入、库存不足拦截、批量发放、幂等校验。
- 飞书消息卡片/机器人承接市场部待审批和待发放提醒。
- 多维表格只作为辅助看板或数据导入导出工具，不作为库存强一致写入入口。

飞书官方支持通过 JSON 导入页面或自定义复合组件，但数据对象、权限、云函数、流程通常需要在 aPaaS 后台配置，或基于应用导出/模板能力整体迁移。也就是说：页面 JSON 可以加速界面搭建，库存业务规则仍要落在数据对象、流程和云函数里。

## 一、推荐数据对象

### 1. material_item 物料主数据

对应当前 `inventory_items`。

核心字段：

| 字段 API | 字段名 | 类型 | 说明 |
|---|---|---|---|
| material_code | 物料编码 | 文本/唯一 | MAT-0001 |
| material_category | 物料品类 | 文本/单选 | 产品折页等 |
| product_model | 产品型号 | 文本/单选 | BellaBot / 无需型号 |
| language | 语种 | 文本/单选 | 英语等 |
| no_model | 是否无需型号 | 布尔 | 由产品型号判断 |
| unit_price | 单价 | 数字 | 可选 |
| initial_stock | 初始库存 | 数字 | 迁移当天库存 |
| current_stock | 当前库存 | 数字 | 由云函数维护 |
| reserved_stock | 已占用库存 | 数字 | 审批通过但未发放时可用 |
| low_stock_threshold | 库存下限 | 数字 | 低库存提醒 |
| status | 启用状态 | 单选 | 启用/停用 |
| material_key | 物料唯一键 | 文本/唯一 | 品类 + 型号 + 语种 |

### 2. material_request 物料申请单

销售发起的一次申请主单。

核心字段：

| 字段 API | 字段名 | 类型 | 说明 |
|---|---|---|---|
| request_no | 申请单号 | 自动编号/文本 | REQ-20260702-001 |
| requester | 申请人 | 人员 | 销售 |
| requester_department | 申请部门/区域 | 文本/部门 | 销售区域 |
| business_type | 业务类型 | 单选 | 物料领取/物料采购/盘点调整 |
| usage_scene | 用途/活动 | 多行文本 | 展会、客户拜访等 |
| expected_issue_date | 期望发放日期 | 日期 | 销售填写 |
| request_status | 审批状态 | 单选 | 草稿/待审批/审批中/已通过/已驳回/待发放/部分发放/已发放/已取消 |
| market_owner | 市场负责人 | 人员 | 处理人 |
| approval_comment | 审批意见 | 多行文本 | 驳回或备注 |
| submitted_at | 提交时间 | 日期时间 | 系统写入 |
| approved_at | 审批时间 | 日期时间 | 系统写入 |

### 3. material_request_line 申请明细

一张申请单下的多条物料明细。

核心字段：

| 字段 API | 字段名 | 类型 | 说明 |
|---|---|---|---|
| line_no | 明细编号 | 自动编号/文本 | LINE-xxx |
| request | 所属申请单 | 关联对象 | material_request |
| material | 物料 | 关联对象 | material_item |
| request_qty | 申请数量 | 数字 | 销售申请数量 |
| stock_snapshot | 提交时库存快照 | 数字 | 提交时记录 |
| approved_qty | 审批通过数量 | 数字 | 市场可调整 |
| actual_issue_qty | 实际发放数量 | 数字 | 市场最终填写 |
| line_status | 明细状态 | 单选 | 待审批/待发放/部分发放/已发放/缺货/取消 |
| issue_user | 发放人 | 人员 | 市场人员 |
| issue_at | 发放时间 | 日期时间 | 系统写入 |
| ledger | 出库流水 | 关联对象 | inventory_ledger |
| shortage_reason | 缺货说明 | 多行文本 | 库存不足时填写 |

### 4. inventory_ledger 库存流水

库存唯一审计账本。不要删除流水，撤回时写反向流水。

核心字段：

| 字段 API | 字段名 | 类型 | 说明 |
|---|---|---|---|
| ledger_no | 流水编号 | 自动编号/文本 | TX-xxx |
| occurred_at | 发生时间 | 日期时间 | 系统写入 |
| ledger_type | 流水类型 | 单选 | 销售领用出库/采购入库/盘点调整/撤回冲销 |
| material | 物料 | 关联对象 | material_item |
| quantity_delta | 数量变化 | 数字 | 入库正数，出库负数 |
| before_stock | 变更前库存 | 数字 | 云函数写入 |
| after_stock | 变更后库存 | 数字 | 云函数写入 |
| source_request | 关联申请单 | 关联对象 | material_request |
| source_line | 关联申请明细 | 关联对象 | material_request_line |
| idempotency_key | 幂等键 | 文本/唯一 | 防止重复扣库存 |
| operator | 操作人 | 人员 | 系统/市场人员 |
| ledger_status | 操作状态 | 单选 | 有效/已撤回/冲销记录 |
| original_ledger | 原流水 | 关联对象 | 撤回时关联 |
| note | 备注 | 多行文本 | 审计说明 |

### 5. stock_operation_batch 批量操作

用于市场部批量发放、批量入库、批量撤回。

核心字段：

| 字段 API | 字段名 | 类型 | 说明 |
|---|---|---|---|
| batch_no | 批次号 | 自动编号/文本 | BATCH-xxx |
| operation_type | 操作类型 | 单选 | 批量发放/批量入库/批量撤回 |
| operator | 操作人 | 人员 | 市场人员 |
| batch_status | 批次状态 | 单选 | 草稿/处理中/成功/部分成功/失败 |
| total_count | 总条数 | 数字 | 系统写入 |
| success_count | 成功条数 | 数字 | 系统写入 |
| fail_count | 失败条数 | 数字 | 系统写入 |
| error_message | 错误信息 | 多行文本 | 系统写入 |

## 二、页面设计

### 1. 销售申请页

目标：销售像使用当前 Streamlit 一样提交多条物料申请。

页面区域：

- 顶部：申请人、部门、业务类型、用途、期望发放日期。
- 明细表格：物料品类、型号、语种、申请数量、当前库存、可用库存。
- 按钮：新增明细、复制明细、删除明细、保存草稿、提交审批。
- 校验：
  - 申请数量必须大于 0。
  - 物料必须启用。
  - 同一申请单内同一物料不允许重复，或自动合并。
  - 若可用库存不足，提交时提示，不一定阻断；是否阻断由业务决定。

### 2. 市场审批工作台

目标：市场部集中处理待审批申请。

页面区域：

- 左侧：待审批申请列表，支持按申请人、区域、期望日期筛选。
- 右侧：申请明细，展示申请数量、当前库存、已占用库存、建议发放数量。
- 按钮：通过、驳回、改数量后通过、标记缺货、批量通过。
- 校验：
  - 通过时审批数量不能大于申请数量，除非管理员权限。
  - 库存不足时要求填写缺货说明，或者阻断审批通过。

### 3. 市场发放工作台

目标：审批通过后，市场填写实际发放数量并一键出库。

页面区域：

- 待发放明细表。
- 支持勾选多行、批量设置实际发放数量。
- 按钮：批量发放、部分发放、取消发放。
- 校验：
  - 实际发放数量必须大于等于 0。
  - 实际发放数量不能大于审批通过数量。
  - 出库前重新读取当前库存，库存不足则阻断。
  - 已生成流水的明细不能重复发放。

### 4. 库存管理页

目标：替代当前 Streamlit 的实时库存页。

页面区域：

- 库存列表：物料编码、品类、型号、语种、当前库存、已占用、可用库存、库存状态。
- 筛选：品类、型号、语种、库存状态。
- 按钮：采购入库、盘点调整、下载/导出、查看流水。
- 校验：
  - 普通市场成员不能直接改当前库存，只能新增入库/调整流水。
  - 盘点调整必须填写原因。

### 5. 管理员配置页

目标：维护物料主数据和基础配置。

页面区域：

- 物料主数据表。
- 新增物料品类/型号/语种组合。
- 批量导入物料。
- 停用物料。

## 三、流程设计

### F1 销售提交申请

触发：销售点击“提交审批”。

动作：

1. 校验申请主单和明细。
2. 写入提交时间。
3. 把申请单状态改为“待审批”。
4. 推送消息卡片到市场群或市场负责人。

### F2 市场审批

触发：市场点击“通过/驳回”。

通过时：

1. 校验每条明细的审批通过数量。
2. 可选：占用库存，写入 `reserved_stock`。
3. 明细状态改为“待发放”。
4. 申请单状态改为“待发放”。
5. 推送给市场发放人员。

驳回时：

1. 申请单状态改为“已驳回”。
2. 写入审批意见。
3. 推送给申请人。

### F3 市场实际发放

触发：市场点击“批量发放”。

动作：

1. 调用云函数 `batch_issue_request_lines`。
2. 对每条明细重新读取当前库存。
3. 库存不足则该条失败并返回原因。
4. 成功项生成出库流水。
5. 更新物料当前库存。
6. 更新申请明细发放状态。
7. 如果所有明细发放完成，申请单状态改为“已发放”；否则改为“部分发放”。

### F4 采购入库/盘点调整

触发：市场在库存管理页点击“采购入库”或“盘点调整”。

动作：

1. 调用云函数 `apply_inventory_change`。
2. 生成库存流水。
3. 更新物料当前库存。
4. 若库存仍低于下限，推送低库存提醒。

### F5 撤回/冲销流水

触发：管理员或市场主管点击“撤回流水”。

动作：

1. 原流水状态改为“已撤回”。
2. 新增一条反向流水，状态为“冲销记录”。
3. 更新物料当前库存。
4. 写入撤回原因。

## 四、云函数清单

### submit_material_request

用于销售提交申请。

入参：

```json
{
  "request_id": "record_id"
}
```

核心逻辑：

- 校验主单必填项。
- 校验至少有一条明细。
- 校验明细数量。
- 写库存快照。
- 更新状态并推送消息。

### approve_material_request

用于市场审批。

入参：

```json
{
  "request_id": "record_id",
  "action": "approve",
  "comment": ""
}
```

核心逻辑：

- 校验审批权限。
- 校验明细审批数量。
- 状态变更。
- 可选占用库存。
- 推送发放提醒。

### batch_issue_request_lines

用于批量发放并出库。

入参：

```json
{
  "line_ids": ["record_id_1", "record_id_2"],
  "operator_user_id": "user_id"
}
```

核心逻辑：

- 防重复：检查每条明细是否已有出库流水。
- 防超发：实际发放数量 <= 审批通过数量。
- 防库存不足：当前库存 >= 实际发放数量。
- 生成出库流水。
- 更新当前库存。
- 更新明细和申请单状态。
- 返回逐条成功/失败结果。

### apply_inventory_change

用于采购入库、盘点调整、手工冲销。

入参：

```json
{
  "material_id": "record_id",
  "ledger_type": "采购入库",
  "quantity_delta": 100,
  "source_request_id": "",
  "source_line_id": "",
  "idempotency_key": "unique-key",
  "note": ""
}
```

核心逻辑：

- 查询物料当前库存。
- 计算变更后库存。
- 出库时禁止变更后库存小于 0。
- 使用幂等键防止重复执行。
- 新增库存流水。
- 更新物料当前库存。

## 五、权限模型

### 销售

- 可创建申请单和申请明细。
- 可查看本人申请。
- 可编辑草稿。
- 不能直接改库存、库存流水、物料主数据。

### 市场专员

- 可查看所有申请。
- 可审批、发放、采购入库。
- 可查看库存和流水。
- 不建议允许删除流水。

### 市场主管

- 拥有市场专员权限。
- 可撤回/冲销流水。
- 可处理异常库存。

### 管理员

- 可维护物料主数据、权限、页面、流程、云函数。

## 六、JSON 导入怎么用

你看到的“导入 JSON 创建页面/复合组件”可以用，但要注意边界：

1. 页面 JSON 通常只负责页面布局、组件树、按钮、绑定、事件。
2. 数据对象和流程并不总是能通过同一个页面 JSON 一起创建。
3. 页面 JSON 里经常包含当前租户/当前应用的组件 ID、数据源 ID、字段 ID；跨应用导入后可能需要重新绑定。
4. 最稳的做法是：先在你们 aPaaS 里建好数据对象，再导入页面 JSON，最后重新绑定数据对象和按钮事件。

我已经在 `outputs/feishu_apaas_blueprint/` 里放了一套蓝图 JSON：

- `data_objects.json`：数据对象字段设计。
- `pages_blueprint.json`：页面和按钮结构。
- `flows_blueprint.json`：流程结构。
- `cloud_functions_blueprint.json`：云函数设计。
- `message_cards/market_request_reminder.json`：市场审批提醒卡片。
- `material_item_import.csv`：从当前 `data/inventory.csv` 转换出来的物料主数据导入模板。

这些 JSON 是“蓝图格式”，用于搭建和校对。它们不是飞书官方页面导出的原生 JSON。如果你希望我生成能直接点“导入 JSON”的页面文件，请先在你们飞书 aPaaS 里：

1. 新建一个空白页面。
2. 放一个简单表格和一个按钮。
3. 从 aPaaS 导出这个页面 JSON。
4. 把导出的 JSON 文件放到本项目里。

拿到这个真实样例后，我就能按飞书当前页面 schema，把销售申请页、市场工作台、库存管理页转换成更接近可直接导入的 JSON。

## 七、推荐实施顺序

1. 建数据对象：先建 `material_item`、`material_request`、`material_request_line`、`inventory_ledger`。
2. 导入物料主数据：导入 `outputs/feishu_apaas_blueprint/material_item_import.csv`。
3. 建云函数：先做 `apply_inventory_change`，再做 `batch_issue_request_lines`。
4. 建销售申请页：完成提交申请主链路。
5. 建市场审批页：完成审批和状态流转。
6. 建市场发放页：完成库存不足拦截和出库流水。
7. 建消息卡片：将待审批/待发放推送到市场群。
8. 做权限：销售、市场、市场主管、管理员分层。
9. 小范围试运行：用 10 条真实物料和 2 名销售试跑。
10. 再迁移旧流水：确认流程稳定后再导入历史库存流水。
